# PRD：助理模式 A2A 单聊与群聊

> 文档版本：V0.3 交互确认稿  
> 更新日期：2026-08-31  
> 适用端：COMAC AI 桌面 Web / 桌面客户端内嵌 Web  
> 关联文档：《PRD-双模式会话与统一Workspace》《PRD-助理A2A任务派发与催办》《PRD-助理长Session消息通知中心》

## 1. 能力定位

A2A 会话是由个人助理代理用户发起和回复的受控协作记录，不是普通 IM，也不是任意 Agent 自由互相调用。

产品采用两个独立维度：

| 维度 | 取值 |
| --- | --- |
| 交互范围 | 单聊 / 群聊 |
| 事项机制 | 通知型 / 目标协作型 |

助理模式左侧提供“我的助理”“定时器”和“A2A 任务”三个直接入口，不展示 A2A 会话列表或任何会话分组。点击“A2A 任务”进入任务看板；个人数字分身配置不再展示 A2A 任务。

## 2. 核心交互原则

- A2A 任务看板负责查看和进入已有单人或多人 A2A 会话；
- 选中任意一种 A2A 会话后，中间区域只展示数字分身的正式会话记录，不提供任何输入框，主持人也不能直接发言；
- 会话右侧固定展示当前用户与自己分身的私人对话，四类会话均采用同一结构；
- 会话页不展示“已完成、进行中”等常驻状态标签，也不展示目标摘要、轮次进度或通知型说明条；状态、目标和轮次仍由底层执行状态机保存；
- 用户通过右侧私人对话告诉分身如何发送、回复、结束或发起下一轮，原始指令仅本人可见；
- 用户完成必要确认后，正式内容才以该用户数字分身的身份写入中间会话记录；
- 需要当前真人判断、授权或确认时，分身必须在右侧调用 Ask User，不能在群聊中替用户推断；
- 助理必须解析稳定会话 ID、参与人、范围和事项机制，正式产品不得只依赖字符串匹配。

## 3. 四种模式

### 3.1 单聊通知

向一个人发送信息。发送和送达即完成，不创建待办、不要求回复、不自动催办。对方可以通过自己的助理自愿回复，但系统不承担闭环责任。

### 3.2 单聊协作

向一个人发起有明确目标的事项。系统记录预期回复人、回复状态、轮次和目标状态；收到回复后回调发起人的助理，由发起人决定完成或继续下一轮。

### 3.3 群聊通知

向多人同步同一信息。系统记录送达和可选已读，不强制参与人回答，不建立回复进度，也不执行顺序发言。

### 3.4 群聊协作

向多人发起共同目标。每轮按照保存的 `speaking_order` 严格调用分身，每位分身最多回复一次；后发言分身可以读取发起消息和本轮全部前序回复。

## 4. 创建与回复

新建会话在“我的助理”中通过自然语言发起：

```text
通知李四下午评审改到三点。
请王五确认供应商本周交付风险。
通知李四、王五年度安排已更新。
和陈工、刘工发起方案评审协作。
```

进入已有会话后，用户在右侧私人分身对话中输入：

```text
在这个会话里回复：继续补充接口风险。
本轮意见已经足够，确认完成协作。
请基于上一轮结论继续下一轮。
```

右侧私人对话中的用户原文不是正式 A2A 消息。分身整理为待发送内容并请求确认，用户确认后才写入中间会话记录。

助理忙碌时：

- 全局“我的助理”长 Session 与各会话右侧私人分身对话使用不同执行上下文；
- 全局助理正在处理其他任务时，用户仍可以在已选 A2A 会话右侧沟通和完成 Ask User；
- 已有会话和正在执行的分身回复不受全局助理忙碌状态影响。

## 5. 通知型与协作型边界

通知型只负责发送、送达、可选已读和保存自愿回复，不负责：

- 创建待办；
- 判断谁未回复；
- 自动催办；
- 判断目标完成；
- 自动发起下一轮。

目标协作型额外负责：

- 保存目标和参与人；
- 跟踪预期回复和实际回复；
- 汇总本轮结果并在发起人的会话右侧私人分身对话中生成 Ask User；
- 提示发起人确认完成、调整目标或继续下一轮；
- 保存每轮上下文和参与顺序。

模型可以建议目标是否完成，但只有发起人可以确认完成或发起下一轮。

## 6. 待本人确认与顺序阻塞

Ask User 是会话执行状态，不是普通未读消息：

- 只有当前用户存在未处理的 Ask User 时，左侧对应会话显示一个红点；
- 普通新消息、送达、分身回复和轮次完成均不显示红点；
- 红点不显示数字，也不代表未读数量；
- 打开会话或读过内容不会清除红点，完成确认后才会消失；
- 多个待确认事项仍只显示一个红点；
- 红点和确认内容只对需要确认的本人可见；
- 用户处于任务模式时，助理全局入口可汇总显示同样的无数字红点，进入助理模式后再定位具体会话。

多人协作严格遵循顺序阻塞：

1. 某一分身需要对应真人确认时，当前轮次立即挂起；
2. 后续分身不得越过该成员继续发言；
3. 主持人只能等待，不能代答、跳过、强制继续或发起下一轮；
4. 对应真人在自己的右侧私人分身对话中完成 Ask User 后，该分身完成正式回复；
5. 当前分身完成后，系统再按 `speaking_order` 调用下一位；
6. 本期不提供超时自动跳过、暂停本轮或终止本轮。

## 7. 目标协作状态

```text
待确认 → 进行中 → 等待回复
                    ├── 等待本人确认 → 完成当前发言 → 继续顺序
                    └── 已收到全部回复
                              ├── 确认完成
                              ├── 发起下一轮
                              └── 调整目标或参与人
```

一期不允许数字分身在没有用户确认的情况下自动关闭目标或连续发起多轮。

## 8. 身份与权限

| 角色 | 一期能力 |
| --- | --- |
| 发起人 | 在“我的助理”中创建会话；在会话右侧私人对话中要求分身发送、完成或继续下一轮 |
| 参与真人 | 查看会话；在自己的右侧私人分身对话中补充信息或完成 Ask User |
| 发起人的数字分身 | 解析意图并代发，消息显示“分身代发” |
| 参与人的数字分身 | 按权限读取本轮上下文并回复，消息显示“分身回复” |

中间 A2A 记录区对所有真人都不提供输入框，正式记录中只有数字分身发言。右侧私人对话不属于 A2A 正式消息流。一期不支持暂停本轮、终止本轮、多主持人和分身自行决定下一位发言者。

## 9. 会话与并发边界

私人助理长 Session 与每个 A2A 会话是独立执行上下文：

```text
assistant_session_id
conversation_id
private_side_session_id（按 conversation_id + user_id 隔离）
round_id（仅目标协作必需）
goal_id（仅目标协作必需）
```

- 会话运行不修改私人助理的执行状态；
- 每个真人在每个 A2A 会话中拥有独立私人分身上下文，内容不对其他成员可见；
- 助理运行不阻止已经开始的分身回复；
- 通知型送达不进入目标跟踪状态；
- 目标协作收到全部预期回复后，通过 A2A 回调更新会话状态，并在发起人的右侧私人分身上下文中生成 Ask User；
- 切换可见页面不改变任何执行状态。

## 10. 页面与 Workspace 边界

| 当前页面 | 主区域 | Workspace |
| --- | --- | --- |
| 我的助理 | 私人长会话 | 展示入口，可按现有方式展开 |
| 任意 A2A 会话 | 中间只读正式记录 + 右侧私人分身对话 | 不展示入口 |
| 外部任务模式 | 普通任务内容 | 展示入口，可按现有方式展开 |

A2A 会话右侧区域固定用于私人分身沟通和 Ask User，不与 Workspace 同时竞争右侧空间。

正式产品还必须保存权限快照、模型和提示版本、投递状态、错误、幂等键和审计记录。

## 12. Demo 与正式产品边界

当前 Demo 使用前端 Mock 人员、会话、关键词解析和定时器模拟顺序回复；页面刷新后不保证保存新会话，不接组织身份、权限、模型、A2A Server 或持久化服务。

正式产品不得把前端字符串匹配、定时器或本地状态作为服务端实现方案。

## 13. 验收要点

1. 助理侧栏按多人通知、多人协作、单人协作、单人通知四组展示；
2. 四组不显示数量，每个会话仍可展示范围与事项机制标签；
3. 预置四种组合用于演示；
4. 四类会话的中间正式记录区域均没有输入框，主持人也不能直接发言；
5. 四类会话右侧均展示当前用户与自己分身的私人对话输入框；
6. 新建会话可从“我的助理”发起，已有会话可从右侧私人对话要求分身代发；
7. 通知型不创建回复进度；
8. 协作型目标、轮次和回复进度保留在底层状态中，当前界面不展示常驻摘要卡；
9. 群聊协作严格按顺序各回复一次；
10. Ask User 只出现在需要确认者自己的右侧私人对话中；
11. 只有待本人确认显示红点，红点无数字且不会因打开会话而消失；
12. 等待本人确认时当前轮次挂起，主持人不能代答、跳过或继续；
13. 完成 Ask User 后红点消失，并按原顺序继续；
14. 收齐回复后不自动发起下一轮；
15. A2A 会话页不展示 Workspace 入口；“我的助理”和任务模式继续保留 Workspace；
16. 全局助理忙碌时，已选 A2A 会话右侧私人对话仍可独立使用。
