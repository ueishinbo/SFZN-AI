01 · Product principles

强曝光，不建设第二个待办中心

面板负责当前决定，Workspace 负责完整上下文，对话负责自然语言。用户可以暂存，但系统不能把外部正式动作藏成一条普通消息。

A

单一交互对象

同一时刻只展示一个决策。不提供上一项、下一项、页码和显式队列。

B

内部 FIFO

新事项不替换当前面板。确认或暂存后，后台等待的下一项立即出现。

C

现场可恢复

输入草稿、光标、聊天滚动、Workspace 标签和目录状态都不能被销毁。

D

任务服务为准

决策和任务文件都是交互与投影，不成为另一套权威任务数据库。

02 · Interruption gate

只有模型输出拥有短暂的“不可打断区”

A2A 事件先经过前台输出门控。用户输入、查看聊天或 Workspace 都不是阻塞条件；这些现场会被冻结并在面板关闭后恢复。

EVENTA2A 决策到达

来自用户当前意图，或来自其他人的数字分身。

→
ONLY GATE模型是否输出中？

是：内部等待。否：无需判断草稿或 Workspace，直接弹出。

→
SURFACE底部决策面板

处理、确认，或点击 X 暂存。完成后恢复原现场。

边界：输出异常结束也视为可见输出结束；后台任务不需要全部完成。已有决策显示时，新事项只进入内部 FIFO，不抢占当前内容。

03 · Decision types

四类决策，共用一个底部交互协议

面板结构统一，但字段和主操作按业务动作变化。普通状态同步、已读和完成通知不生成面板。

04 · Workspace integration

面板做决定，文件保存上下文

没有“查看详情”按钮。面板直接提供当前决定所需的最小信息；完整任务、事件和暂存状态始终沉淀到 Assistant Workspace。
