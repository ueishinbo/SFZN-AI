侧栏“助理任务”进入任务列表，列表只显示任务及进展/待处理提示，不再展开 A2A 子列表。进入任务后，左侧是唯一私人任务对话，右侧是协作过程/任务资料；协作顶部选择器切换各路单聊或群聊。

本地预览：http://127.0.0.1:5175/SFZN-AI/?view=a2a 。上述 GitHub 链接由 main 分支发布工作流更新，具体部署结果以 GitHub Actions 为准。

本期任务删除、撤销删除、已删除列表及恢复进行中已从原型移除；完成后保留历史查看。动态等其他会议事项仍待逐项讨论。旧原型保存的删除标记不再参与列表过滤，不清除任务、对话或文件数据；这只是演示数据兼容，不提供恢复功能。

### 我的助理欢迎引导（2026-10-25 精简）

欢迎消息只保留两个示例：自然语言建立任务、发起数字宠物需求讨论。已有任务统一从“助理任务”进入，左侧私人讨论，右侧查看协作和资料。

已从欢迎引导移除过时的“写入 C 项目管理平台派任务”“仅 A2A 原生任务”及独立侧栏会话入口说明；同时移除长任务阻塞、子智能体失败重试、专项评审、表单导航、自动催办等旁支演示口令，以及重复的单聊/群聊通知和协作示例。本次精简范围为首页引导，不代表删除对应历史功能或下方业务场景。模型长期记忆和真实工具调用不再作为欢迎消息中的能力承诺。

## 2. 推荐先演示的六条完整路径

### T01 一个任务、两路沟通

1. 从列表进入“完成数字宠物首期需求方案”，查看左侧私人任务对话与整体目标/进展。先处理自动展开的评审 Ask User，再进行后续私人讨论与发送演示。
2. 右侧选择器切换“桌面数字宠物首期需求评审”和“数字宠物测试进度跟进”；左侧消息与未发送草稿不变。
3. 在测试跟进中点击某条“与助理讨论这条消息”，输入区出现协作名称与引用。输入“帮我理解一下刚才的时间承诺，先别发送”，只新增私人任务消息。
4. 保留该引用，输入“下一轮 @陈工 请确认启动测试还缺哪些材料”；消息进入测试跟进，评审群不新增消息。模拟回复与结果汇入任务主会话。
5. 有待确认问题时左侧直接展开 Ask User，无关闭或稍后处理；先选择结果才能继续普通讨论。有多项问题时在面板内切换，处理完一项自动显示下一项；右侧当前问题显示正在处理，其他问题提供切换处理。
6. 点击任务资料、预览文件并返回列表，再切回协作过程，仍停留在同一任务。顶部返回按钮才回任务列表。

右侧选中只控制查看；引用、明确点名及缺项选择才决定发送对象。已结束协作禁止新发送，仍可查看和私人讨论。

### T02 在主任务输入区调用 Ask User

在数字宠物主任务输入“帮我建个群”：

1. 输入区先补沟通目标，例如“确认数字宠物点击、拖动和免打扰的交互边界”。
2. 使用人员选择器选陈工、林悦；同一个人不重复加入，本人自动是发起人。
3. 选择最大 3 轮，点击“创建并发送”。
4. 原型留在主任务，回复实际名称、人员、轮次和会话链接；新会话出现在同一任务下。
5. 右侧自动选中新协作并展示首条消息，左侧始终是原任务。任一步选择“取消创建”不创建、不发送。

此处还可使用完整指令：“帮我拉陈工、刘工建个群，确认数字宠物首期交互边界，最多3轮”。当前受限规则可识别该表达并跳过缺项面板；这不是任意自然语言解析的能力承诺。新群与既有评审会话独立，不替换既有群。

### T03 无来源、无 A2A 的任务

1. 右上角“新建任务”，进入我的助理，预填“帮我推进［具体事项］，希望最终［达成什么结果］”并选中第一空。填写“整理产品发布检查清单”，结果可填“汇总需要确认的事项”，发送后点击查看任务。
2. 不必选择 C 大脑任务或成员，就能进入任务主会话。
3. 输入“整理一份推进清单”，原型生成可打开的 Markdown 演示文件，消息、Workspace 和任务详情均能访问。
4. 点击任务详情，查看目标、当前进展、文件和动态；无 A2A 时显示会话空态。

补充验证：默认原文或仅填写第二空时不可创建；只替换第一空、保留第二空占位也能创建，提交记录和任务中不留下占位尾句。不提供取消新建按钮；清空预填内容即可放弃，改问普通问题不创建任务。

也可从我的助理输入“创建任务，整理产品发布检查清单”，点击“查看任务”。当前通过有限触发词识别建立委托，尚未接入自动识别与去重服务。

### T04 阻止误结束尚在沟通的任务

1. 对“完成数字宠物首期需求方案”点击左侧勾选或更多菜单“标记已完成”。
2. 弹窗列出实际未结束的 A2A，会话数按当前演示状态计算；“确认完成”禁用，可点会话入口处理。
3. 取消后任务仍保持进行中。
4. 在具体会话中结束只影响该会话；主任务不会自动完成。如果本人是某会话成员，不能越权代替群主关闭会话。

### T05 完成与历史查看

使用 T03 创建的无 A2A 演示任务验证：

1. 从主任务返回列表，勾选任务；在“确认任务完成”中确认。弹窗明确完成后不能恢复进行中。
2. 任务进入已完成，勾选不可操作；列表与详情更多菜单都仅保留“编辑名称”。
3. 进入任务，主会话只读，历史记录与文件仍可查看；底部提示如需继续推进请新建任务。
4. 刷新后仍保持已完成，任务记录和文件继续存在。
5. 列表无“已删除”入口，菜单无删除/恢复操作，也没有删除撤销提示。

不要为了展示主任务完成而把尚需讨论的业务群全部关闭。已结束的 A2A 保持只读。

### T06 两处编辑与一致性

1. 在列表某任务的更多菜单选择“编辑名称”，核对弹窗仅带入被点任务的名称，无目标编辑项；空白名称不可保存，取消不改任何值。
2. 保存修改后，列表、主会话标题、任务详情与返回任务名称一致，原任务目标保持不变。
3. 进入相关 A2A：其会话名称和目标不因父任务改名而改写；有来源时引用名称也保持原值。
4. 查看任务动态中的更新记录；编辑已完成任务仍保持已完成。

## 3. 七个 A2A 业务场景

| 会话 | 所属主任务 | 本人身份 | 初始沟通情况与重点 |
| --- | --- | --- | --- |
| 用户研究工具采购咨询 | 用户研究工具采购准备 | 发起人 | 一轮、已结束；采购资料与附件，咨询结束不等于采购办理完成。 |
| 数据服务合同条款澄清 | 用户研究工具采购准备 | 发起人 | 法务首轮已回；@指定回复，合同仍有待补条款。 |
| 桌面数字宠物首期需求评审 | 完成数字宠物首期需求方案 | 发起人 | 首轮待我处理；第二/三轮明确轻量陪伴方向、交互边界与分工。 |
| 数字宠物测试进度跟进 | 完成数字宠物首期需求方案 | 发起人 | 两轮后仍在办；本人和测试单独核实材料与安排，体现同任务一对多。 |
| 短信服务续约与大促容量确认 | 完成双十一短信服务保障 | 发起人 | 三轮后等待继续；核对额度和吞吐量，不虚构扩容已完成。 |
| 总部周例会材料确认 | 总部周例会材料确认 | 成员 | 李四是群主；本人确认材料时间，不自行关闭群。 |
| 产品增长周会调整通知 | 产品增长周会调整通知 | 成员 | 刘工是群主；通知及议程附件，不自动写日历。 |

其他年度任务、供应链观察者内容是保留的演示数据，并非本轮新增业务能力。以下场景优先用于解释任务与 A2A 的关系。

### S01 用户研究工具采购咨询

进入“用户研究工具采购准备”，在右侧选择已结束的“用户研究工具采购咨询”。主任务本身仍在进行中，采购咨询结束并不代表采购准备全部完成。产品团队咨询20个年度SaaS账号的采购流程，采购说明预算、报价及用户访谈录音的数据处理材料。打开“用户研究工具采购材料清单.md”，再返回文件列表。咨询已结束，输入只读；没有下单、付款或签约。

### S02 短信服务续约与大促容量确认

查看三轮记录：第一轮发现活动预测120万条、当前剩余70万条，差额50万条；第二轮区分交易/营销通道及吞吐量，站内信不能替代验证码；第三轮明确采购追书面方案、运营补预测并联系研发复核。Workspace清单与聊天数字、责任人一致。

顶部不显示“已暂停”标签；当前进展说明已完成3轮、等待发起人决定是否继续。输入“下一轮，请确认是否收到短信扩容的书面方案”，可以开始第四轮；预设回复仍为未确认，不能凭空变成扩容完成。结束时点击右侧“结束本次协作”，在左侧确认；任务完成与结束协作仍是两种操作。

### S03 桌面数字宠物首期需求评审

1. 在“助理任务”筛选待我处理，展开“完成数字宠物首期需求方案”，点击“桌面数字宠物首期需求评审”；已有发起人的开场消息及测试、研发首轮回复。
2. 私人对话说明希望桌面宠物有陪伴感，同时避免开会和工作时被打扰。首轮提出置顶、全屏隐藏、收起恢复和多任务状态问题。
3. Ask User选择“先按轻量陪伴方案讨论”，第二轮围绕展示、拖动、点击唤起、无声状态反馈展开，暂不讨论自主聊天或声音提醒。
4. 继续第三轮，测试补多屏、越界、全屏及状态切换用例，研发拆悬浮层、唤起、状态映射和偏好设置；美术资源、优先级与排期仍待确认。第三轮结束后不自动进入下一轮，当前进展提示等待发起人决定是否继续。
5. 选择“先不继续”不发送下一轮消息；之后可以输入“下一轮，请按轻量陪伴方案核对交互边界”。
6. 这个场景演示需求沟通，不是已经开发、生成或安装了数字宠物。

### S04 数据服务合同条款澄清

用户已经在我的助理中确认建群，分身自动发送首条消息并@法务周宁，首轮法务意见已收到；不存在进入会话再确认发起的阶段。

1. 右侧查看首条正式询问和周宁关于删除时限、删除证明、自动续费提醒的答复。
2. 中间私人对话解释“初步意见不等于合同通过”，再拟定安全补问草稿。只有这条后续补问尚未发送。
3. 输入“下一轮，@许晨 请回复数据存储与分包商需要补充的材料”，仅安全许晨回复，其他成员仍可查看。
4. 需要继续核对所有人意见时，另起一轮输入“下一轮，请回复还需要供应商补充哪些材料”，不指定@，法务和安全各回复一次。
5. 输入“帮我分析这些条款，先别发”不增加公开消息；输入“下一轮，@不存在的人 请回复”被拦截。通信不产生合同签署或审批通过结论。

### S05 总部周例会材料确认

李四发起周三总部例会材料收集，王五确认采购进度表中仍有待核实交期，陈智超需要确认项目进展与风险材料的提交时间。

私人对话说明两项里程碑口径尚待核实，不能把上周数据视为本周结论。Ask User提供：

- 回复尚需核实：不承诺周二17:00前给到材料。
- 确认可以周二提供：本人承诺提供汇总版本，未确认数据单独标注，不等于所有数据已核定。
- 暂不发送：保留私人讨论，不外发。

成员不能标记整个会话完成或自行开启下一轮；回复后等待李四推进。不自动上传材料或提交汇报。

### S06 产品增长周会调整通知

刘工通知周三14:00会议改到星云会议室，议题为注册转化、会员活动、增长实验。查看议程附件，核对时间地点一致。没有 Ask User，没有自动写日历。

### S07 数字宠物测试进度跟进：同一来源，一对多协同

1. 在“助理任务”展开“完成数字宠物首期需求方案”，点击“数字宠物测试进度跟进”。顶部参与人只有陈智超与测试陈工；来源为“完成数字宠物首期需求方案”，与多人需求评审保存同一个来源平台、应用和任务标识。
2. 中间私人对话说明为何单独沟通，右侧两轮记录核实“尚未启动测试”的原因：内部体验包版本、入口及变更清单未明确。需求评审仍有未定规则，不推定已经正式提测或需求定稿。
3. 第二轮明确陈工16:00反馈材料是否齐备及测试安排；不是测试完成承诺。输入“下一轮，请确认待测材料是否齐备”可继续询问，预设回复仍不虚构已经开测。
4. 点击左上角返回所属主任务，再从该任务的相关会话进入多人需求评审：参与人仍为陈智超、陈工、刘工，继续处理需求范围问题。两会话共享主任务与来源引用，各自的通信轮次、待处理请求和完成状态独立。每个会话 Workspace 只列本群已共享文件；主任务可汇集本人可读的两群附件。
5. 在测试跟进会话输入“任务完成了”并确认，仅结束本次询问；需求评审保持原状态，平台任务不被完工。结束催办也不表示测试通过。

演示顺序建议：主任务 → 多人需求评审 → 返回主任务 → 测试进度跟进 → 返回主任务查看汇总，对比共同目标、不同人员和独立沟通状态。

## 4. A2A 私人对话的演示层次

六个场景均预置了多条“本人—分身”往返记录，可在中间向上滚动查看完整背景。它们是演示历史，不是本次打开页面时新执行的操作。

| 场景 | 私人对话展开的重点 |
| --- | --- |
| 工具采购 | 说明采购背景→补充录音数据顾虑→授权询问→解释采购答复→本人确认咨询结束 |
| 短信容量 | 明确保障交易通知→解释50万条缺口→指出额度与吞吐量不同→逐轮汇报→保留未解决风险 |
| 数字宠物需求 | 说明陪伴目标→明确不打扰→梳理研发测试问题→提出轻量首期方案→Ask User决定下一轮方向 |
| 合同澄清 | 建群开场已发送→汇报法务意见→解释审核边界→私人拟定安全补问→本人决定下一轮 |
| 总部周例会 | 收到材料询问→本人说明口径未核实→不替本人承诺→明确待确认标记→Ask User确认 |
| 增长周会 | 说明变更→回答是否新增材料→本人不要求回执或日历变更→保持仅通知 |

继续操作时，每轮结束会在中间汇报本轮实际参与者的意见。全员回复且存在预设摘要时使用固定摘要；仅@一人时只引用该人的本轮回复，不把未回复成员的意见写成已收到。一般自由提问仍采用原有演示兜底，未接入通用模型。

## 5. 我的助理自然语言建群剧本

1. 用户在「我的助理」输入：**帮我建个群讨论数字宠物需求**。
2. 分身说明先补齐目标、参与人和最大轮次；底部输入区出现 Ask User「这次讨论希望解决什么问题？」。用户选择「明确数字宠物首期功能范围及暂不做的内容」，或自行填写具体目标。
3. 同一输入区切换到「邀请哪些同事参加讨论？」。用户勾选陈工、刘工，点击下一步；群主自动为本人，不需要再勾选自己。
4. 输入区切换到「本次最多进行几轮沟通？」。用户选择3轮（也可选1轮、5轮或填写正整数）。面板明确提示选择后创建并发送，到达上限后暂停，等待群主明确要求继续。
5. 分身使用实际选择创建群聊，将用户确定的目标作为首条通信内容，回复创建结果及会话文字链接。无需进入会话再次确认创建或首条消息。

前三步期间没有正式群聊和外发消息；任一步取消都停止本次创建并恢复普通输入框。已回答的目标和人员在助理对话中留存供核对。该演示为固定多步剧本，不代表任意自然语言解析已接入；正式产品按P01-04只问缺失的信息，不对信息齐全的请求重复提问。

## 6. 当前实现与正式 PRD 的差异

| 能力 | 当前原型 | 正式要求或待定边界 |
| --- | --- | --- |
| 主任务与生命周期 | 列表、主会话、详情、编辑、完成门禁及完成后历史查看可操作并在浏览器保存。 | 真实身份、权限、多端保存、重复操作与并发状态复核仍需服务联调。 |
| 自然语言与 Ask User | 主任务支持受限指令和分步补目标/人员/轮次；我的助理有固定数字宠物建群脚本。 | 识别同义表达、歧义、改口、归属去重按 P01/P04 验证；不能把触发词当正式产品限制。 |
| 扫描发现待办后建立任务 | 尚无真实 C 大脑扫描、发现后 Ask User 建任务及去重流程；现有手动建任务不代表已实现该入口。 | P01-10：扫描本人待办→说明来源与查询时间→Ask User 同意后建立任务；暂不创建不改业务状态。扫描频率与再次提醒见 D12。 |
| 上游 A2A 交接后建立任务 | 现有成员会话为预设场景，尚无真实接收端自动建任务与挂接过程。 | P01-10：明确交接直接建立或复用接收人的任务并挂接收到会话，不重复建群、不改变群主、不代执行业务开工。与扫描同时触发只建立一次。 |
| 主任务向已有群跟进 | 明确点名、引用或补齐选择后，在任务内送入原模拟通信引擎；实际发送成功/轮次拦截反馈回任务主会话。 | 用户明确发送且信息完整时遵守 D01，不重复确认；正式实现应回报实际发送结果。 |
| 汇总与动态 | 固定场景摘要、模板推进清单、前端事件与会话最近反馈；部分日期为演示文本。 | 通用摘要、逐条来源追溯、完整真实时间线和模型失败恢复尚未接入；不得当作业务执行日志。 |
| A2A 回合 | 有一人每轮一次、达到轮次上限等待、继续一轮与指定 @ 的演示。回复按模拟定时器出现。 | 并发真实通信、消息回执、重试及超时细则需联调；默认等待时长仍待 D02。 |
| 轮次输入 | 原型提供 1/3/5 轮和自填；主任务建群输入限制为 1—50 正整数。 | 50 是原型约束，正式数值上限及追加规则仍待 D04，不视为已定。 |
| 文件 | 主任务汇集实际演示附件和本人材料；A2A 仅显示本会话正式附件。预览当前以 Markdown/HTML 为主；主任务上传暂支持 MD/TXT/HTML、5 MB 以内。 | 正式数量和大小继承平台，不沿用此原型专用数值。格式、材料共享入口和真实权限见 D05。 |
| 文件现场与空态 | 两处均可列表→预览→返回；部分重新挂载会重置预览位置，主任务仍复用了“当前会话暂无文件”文案。 | WS-01/WS-02 要求按任务/会话区分空态并保持对应文件现场。 |
| 来源与成员隔离 | 来源快照、所属任务和群主/成员入口可展示；来源链接为虚构演示，不连接业务平台。 | 原系统登录回跳、访问权限、接收端归属和真实多账号可见性尚未验证。 |
| 自动结束 | 可演示群主自然语言完成→Ask User→只读；既有已结束场景为预设数据。 | 模型自动完成仍待 D10，不能声称已经跑通。 |

所有当前实现差异均不自动改写主 PRD 的正式要求。任何外部业务任务没有因本原型操作而开工、填表、提交或完工。
