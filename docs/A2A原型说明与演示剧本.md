# A2A 原型演示剧本与功能覆盖

更新：2026-10-15。本文描述本地 Demo 的实际演示路径；业务名称、数量、交期和附件为虚构演示资料，不是 C 大脑查询结果或正式采购制度。新增业务剧本以陈智超为当前用户的演示视角，建议使用“陈智超 · 已有分身”账号。刷新页面恢复初始剧本。正式需求见主 PRD。

## 事项聚合版原型评审（2026-10-15）

协同首页试行“来源事项 → 相关会话”列表，替代三列看板。此为本轮交互评审版本；主PRD中的三列布局待本轮评审后统一修订，通信权限、完成规则不变。

- 同平台、同应用、同来源任务标识的会话归组；名称采用该来源最早记录的快照。未引用来源的会话独立展示。
- 顶部全部／待我处理／进行中／已完成按会话筛选和计数。筛选保留来源事项，显示当前匹配数与全部会话数。含待处理会话的事项优先展示。
- 点击箭头展开收起，点击来源事项标题打开右侧概览，点击会话进入详情。返回列表保留筛选、展开及滚动位置。
- 概览包含协作进展、相关会话、相关材料、关键动态。摘要使用现有剧本的轮次总结与当前待处理问题，不调用实时模型；材料取实际会话附件。动态选取首条消息、附件消息、最新消息，不声称为完整执行日志。
- 材料点击直接进入来源会话的Workspace文件预览；动态点击定位并高亮原消息。查看原任务遇到无链接的演示来源时给出提示，不伪造跳转。
- 概览底部“发起相关会话”带入来源任务，目标和人员重新填写；取消不新增，表单失败保留输入。全局新建默认无来源。
- 详情返回、已完成只读、材料空态、筛选无结果、来源不可访问均保留独立语义；父事项没有完成勾选框，不根据子会话完成推算业务完成度。

建议先打开“完成数字宠物首期需求方案”：展开能同时看到首期评审和测试跟进；筛选待我处理时只展示首期评审。再打开“完成双十一短信服务保障”概览，点击“大促短信容量跟进清单.md”验证材料预览；从概览发起相关会话检查来源继承。

本地演示未接入实时模型摘要更新或真实权限服务，摘要生成中／失败重试、权限变更由正式联调实现，本版不模拟后台已完成这些能力。

## 1. 推荐演示顺序

先看一轮工具采购咨询，再看三轮短信容量核对，接着现场推进桌面数字宠物需求评审。随后切换到法务合同场景演示@，再以成员身份确认总部周例会材料交期，最后看普通会议通知。

顶部常驻目标与当前进展；中间是私人分身对话和 Ask User；右侧为协作记录与 Workspace。顶部参与人入口可展开姓名、身份和轮次。摘要为固定演示内容，不是模型实时推理。

### S01 用户研究工具采购咨询

从已完成栏进入。产品团队咨询20个年度SaaS账号的采购流程，采购说明预算、报价及用户访谈录音的数据处理材料。打开“用户研究工具采购材料清单.md”，再返回文件列表。咨询已结束，输入只读；没有下单、付款或签约。

### S02 短信服务续约与大促容量确认

查看三轮记录：第一轮发现活动预测120万条、当前剩余70万条，差额50万条；第二轮区分交易/营销通道及吞吐量，站内信不能替代验证码；第三轮明确采购追书面方案、运营补预测并联系研发复核。Workspace清单与聊天数字、责任人一致。

顶部不显示“已暂停”标签；当前进展说明已完成3轮、等待发起人决定是否继续。输入“下一轮，请确认是否收到短信扩容的书面方案”，可以开始第四轮；预设回复仍为未确认，不能凭空变成扩容完成。结束时输入“任务完成了”并确认，仅结束本次沟通。

### S03 桌面数字宠物首期需求评审

1. 从待我处理进入，已有发起人的开场消息及测试、研发首轮回复。
2. 私人对话说明希望桌面宠物有陪伴感，同时避免开会和工作时被打扰。首轮提出置顶、全屏隐藏、收起恢复和多任务状态问题。
3. Ask User选择“先按轻量陪伴方案讨论”，第二轮围绕展示、拖动、点击唤起、无声状态反馈展开，暂不讨论自主聊天或声音提醒。
4. 继续第三轮，测试补多屏、越界、全屏及状态切换用例，研发拆悬浮层、唤起、状态映射和偏好设置；美术资源、优先级与排期仍待确认。第三轮结束后不自动进入下一轮，当前进展提示等待发起人决定是否继续。
5. 选择“先不继续”不发送下一轮消息；之后可以输入“下一轮，请按轻量陪伴方案核对交互边界”。
6. 这个场景演示需求沟通，不是已经开发、生成或安装了数字宠物。

### S04 数据服务合同条款澄清

用户已经在我的助理中确认建群，分身自动发送首条消息并@法务周宁，首轮法务意见已收到；不存在进入会话再确认发起的阶段。

1. 右侧查看首条正式询问和周宁关于删除时限、删除证明、自动续费提醒的答复。
2. 中间私人对话解释“初步意见不等于合同通过”，再拟定安全补问草稿。只有这条后续补问尚未发送。
3. 输入“下一轮，@许晨 请回复数据存储与分包商需要补充的材料”，仅安全许晨回复，其他成员仍可查看。
4. 刷新后输入“下一轮，请回复还需要供应商补充哪些材料”，不指定@，法务和安全各回复一次。
5. 输入“帮我分析这些条款，先别发”不增加公开消息；输入“下一轮，@不存在的人 请回复”被拦截。通信不产生合同签署或审批通过结论。

### S05 总部周例会材料确认

李四发起周三总部例会材料收集，王五确认采购进度表中仍有待核实交期，陈智超需要确认项目进展与风险材料的提交时间。

私人对话说明两项里程碑口径尚待核实，不能把上周数据视为本周结论。Ask User提供：

- 回复尚需核实：不承诺周二17:00前给到材料。
- 确认可以周二提供：本人承诺提供汇总版本，未确认数据单独标注，不等于所有数据已核定。
- 暂不发送：保留私人讨论，不外发。

成员不能标记整个会话完成或自行开启下一轮；回复后等待李四推进。不自动上传材料或提交汇报。

### S06 产品增长周会调整通知

刘工通知周三14:00会议改到星云会议室，议题为注册转化、会员活动、增长实验。查看议程附件，核对时间地点一致。没有 Ask User，没有自动写日历。

## 2.1 私人分身对话的演示层次

六个场景均预置了多条“本人—分身”往返记录，可在中间向上滚动查看完整背景。它们是演示历史，不是本次打开页面时新执行的操作。

| 场景 | 私人对话展开的重点 |
| --- | --- |
| 工具采购 | 说明采购背景→补充录音数据顾虑→授权询问→解释采购答复→本人确认咨询结束 |
| 短信容量 | 明确保障交易通知→解释50万条缺口→指出额度与吞吐量不同→逐轮汇报→保留未解决风险 |
| 数字宠物需求 | 说明陪伴目标→明确不打扰→梳理研发测试问题→提出轻量首期方案→Ask User决定下一轮方向 |
| 合同澄清 | 建群开场已发送→汇报法务意见→解释审核边界→私人拟定安全补问→本人决定下一轮 |
| 总部周例会 | 收到材料询问→本人说明口径未核实→不替本人承诺→明确待确认标记→Ask User确认 |

继续操作时，每轮结束会在中间汇报本轮实际参与者的意见。全员回复且存在预设摘要时使用固定摘要；仅@一人时只引用该人的本轮回复，不把未回复成员的意见写成已收到。一般自由提问仍采用原有演示兜底，未接入通用模型。

## 4. 演示边界

- 本版是确定性剧本，不是通用模型；配置了第二、三轮不同业务回复，超过已配置轮次时只提示没有更多已核实信息。
- 模拟回复按定时器先后出现，不代表真实并行A2A通信、跨账号消息收发或后端权限验证。
- 不连接 C 大脑，不提交表单、不修改业务任务、不自动开工。
- 接收方发送后等待发起人，没有模拟另一个真实账号自行继续轮次。
- 真实超时、模型总结、自动完成判定、网络发送失败、全格式文件权限由开发实现；不把它们标成已演示。
- 旧演示说明保存在历史版本目录，旧布局、归档规则不作为本版依据。


## 业务来源标识演示

在“短信服务续约与大促容量确认”或“桌面数字宠物首期需求评审”中，点击标题旁“来源：C大脑任务”，展开来源任务、来源平台和“查看原任务”。不设置“说明”字段。来源正式任务名与会话名不同，分别表达业务工作项与本次沟通目标。点击入口显示演示未接入提示，不访问虚构业务地址。

采购咨询等无来源剧本不显示标签；测试进度跟进与数字宠物需求评审共享同一来源，见 S07。来源任务采用引用时名称，不自动跟随原系统改名；来源删除、不可访问或完成均不改变会话状态。规则及真实接入验收见主 PRD P03-11。原型仅演示来源展示，不代表已接通真实平台查询或回跳。


### S07 数字宠物测试进度跟进：同一来源，一对多协同

1. 从进行中进入“数字宠物测试进度跟进”。顶部参与人只有陈智超与测试陈工；来源为“完成数字宠物首期需求方案”，与多人需求评审保存同一个来源平台、应用和任务标识。
2. 中间私人对话说明为何单独沟通，右侧两轮记录核实“尚未启动测试”的原因：内部体验包版本、入口及变更清单未明确。需求评审仍有未定规则，不推定已经正式提测或需求定稿。
3. 第二轮明确陈工16:00反馈材料是否齐备及测试安排；不是测试完成承诺。输入“下一轮，请确认待测材料是否齐备”可继续询问，预设回复仍不虚构已经开测。
4. 返回多人需求评审：参与人仍为陈智超、陈工、刘工，继续处理需求范围问题。两会话共享来源引用，不共享通信轮次、待处理请求、文件和完成状态。
5. 在测试跟进会话输入“任务完成了”并确认，仅结束本次询问；需求评审保持原状态，平台任务不被完工。结束催办也不表示测试通过。

演示顺序建议：多人需求评审 → 展开来源 → 返回看板 → 测试进度跟进 → 展开同一来源及两位参与人，对比不同目标与独立进展。


## 助理模式自然语言建群剧本

1. 用户在「我的助理」输入：**帮我建个群讨论数字宠物需求**。
2. 分身说明先补齐目标、参与人和最大轮次；底部输入区出现 Ask User「这次讨论希望解决什么问题？」。用户选择「明确数字宠物首期功能范围及暂不做的内容」，或自行填写具体目标。
3. 同一输入区切换到「邀请哪些同事参加讨论？」。用户勾选陈工、刘工，点击下一步；群主自动为本人，不需要再勾选自己。
4. 输入区切换到「本次最多进行几轮沟通？」。用户选择3轮（也可选1轮、5轮或填写正整数）。面板明确提示选择后创建并发送，到达上限后暂停，等待群主明确要求继续。
5. 分身使用实际选择创建群聊，将用户确定的目标作为首条通信内容，回复创建结果及会话文字链接。无需进入会话再次确认创建或首条消息。

前三步期间没有正式群聊和外发消息；任一步取消都停止本次创建并恢复普通输入框。已回答的目标和人员在助理对话中留存供核对。该演示为固定多步剧本，不代表任意自然语言解析已接入；正式产品按P01-04只问缺失的信息，不对信息齐全的请求重复提问。
