# 后台岗位智能体配置改版

更新：2026-09-09。本文为本次后台配置的增量基线，覆盖旧方案中相冲突的创建入口、页面结构、能力地图和输出模板/评测用例配置要求。

## 需求理解

创建岗位智能体仍分两步：点击新建，先展开组织架构树，单选具体岗位；确认后才进入配置页面。配置左侧保留同一组织树，展开到并高亮刚选中的岗位。组织节点负责展开，岗位节点负责选择；所属岗位和可添加范围是两个不同概念。

右侧统一新建与已有草稿的配置布局，顺序为能力地图、岗位画像、能力配置、版本记录。每次只展示一个模块，切换不丢失未保存内容。保存、撤销和离开提醒沿用已有规则。

## 能力地图

能力地图独立于岗位画像，位于第一项。它是 C 大脑已建模业务本体的岗位视图，展示流程、活动节点、岗位职责和节点间的交接关系，不再用可自由增删的文字卡片冒充流程模型。

数据关系：一个岗位关联多个流程，一个流程包含多个活动节点，一个岗位可承担同一流程内多个节点。节点保留稳定 ID、责任岗位、输入、输出、关联知识和规则；边保留前后节点 ID 与流转条件，允许分支、汇聚及返工回路。正式产品根据岗位 ID 查询本体服务并记录来源模型及版本，不能按岗位名称猜测模型。

交互：左侧选择参与流程，中央展示完整流程及方向，突出当前岗位承担的节点；点击任意节点查看责任岗位、输入、输出、上游/下游与流转条件。默认选中本岗位节点，切换流程重新定位。只读查看模型；更新来自本体建模，不在岗位配置中直接修改流程。没有模型时明确显示未关联状态，不编造链路；旧版文字能力内容作为待关联资料保留。

## 岗位画像与能力配置

岗位画像仅保留名称、岗位职责、知识地图与行为规则；职责与规则采用阅读优先、按需编辑，避免默认铺开多块大文本框。能力配置只选择技能与 MCP 等现有资源引用。

移除新建和已有草稿的输出模板、评测用例配置入口，并取消依赖它们的必填检查。历史数据兼容保留，不能因为入口消失而阻止草稿后续提交。发布治理与审批不是本次整体重做的对象。

## 交互边界及验收

- 未选岗位不能确认；取消第一步不创建草稿。
- 确认岗位后创建草稿并进入配置；复制也必须确认所属岗位。
- 所属岗位写入定义，不随名称修改而改变；组织树不能静默切换并覆盖当前配置。
- 模块切换保留修改；离开未保存配置需沿用丢弃确认。
- 已有草稿与新建共享同一配置界面。历史对象没有岗位 ID 时显示待关联并可在草稿中选择，不能推断为已关联。
- 至少演示一个岗位参与两条流程、同流程多个本岗位节点和带条件的返工边。
- 正式服务对模型来源、加载失败、无权限和版本更新提供明确状态。当前 Demo 使用集中 Mock 流程快照，不代表已连接 C 大脑。
