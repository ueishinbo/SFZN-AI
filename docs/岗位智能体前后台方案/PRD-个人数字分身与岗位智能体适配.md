## 1. 产品原则

1. 个人数字分身仍是一人一个；一人可添加多个岗位智能体；
2. 岗位智能体是新增一级模块，不替代用户心智、能力、知识库、分身评测等现有模块；
3. 个人继续添加和管理专家、技能、MCP；岗位智能体带来的能力与个人能力统一汇总；
4. 前台不显示能力来源，不做个人能力与岗位能力的优先级或冲突处理；
5. 知识库由个人数字分身维护，仅影响本人；岗位智能体不绑定知识库；
6. 个人只能查看岗位智能体已发布内容，看不到后台草稿、评测、审批和进化治理信息。

## 3. 岗位智能体模块

### 3.1 主页面

```text
岗位智能体                                      [+ 添加岗位智能体]

┌──────────────────────┐  ┌──────────────────────┐
│ V1.2                 ×│  │ V1.0                 ×│
│ 功能型产品经理智能体   │  │ 交互型产品经理智能体   │
│ 拆解需求并形成产品方案 │  │ 梳理流程和交互方案     │
│ [● 已启用]      [查看] │  │ [● 已启用]      [查看] │
└──────────────────────┘  └──────────────────────┘
```

卡片展示：当前发布版本、名称、一句话目标、启停开关、查看入口和移除入口。卡片不展示人员范围、维护人、后台状态、能力数量或来源。

### 3.2 添加

点击“添加岗位智能体”打开弹窗。列表只展示同时满足以下条件的对象：

- 后台状态为已发布；
- 当前用户命中组织、小组或指定用户范围；
- 当前尚未添加。

列表项展示名称、版本、一句话目标和“添加”按钮。添加成功后立即进入主页面卡片列表，并将其能力合并到现有能力模块。

### 3.3 启停与移除

- 启用：该岗位智能体参与数字分身运行，其能力进入当前可用能力集合；
- 停用：保留添加关系和卡片，但暂不参与运行；
- 移除：二次确认后取消添加关系，卡片消失，并重新进入可添加列表；
- 停用或移除不得删除个人知识、个人画像、任务记录和其他能力配置。

### 3.4 查看详情

个人详情为后台发布内容的只读视图，显示：岗位目标、岗位说明书、核心职责、交付物、工作边界、SOP、输出模板和能力摘要。

不显示：后台维护人、可添加范围、草稿、评测、审批、进化建议、内部操作记录。详情页不提供编辑岗位配置按钮。

## 4. 能力合并

个人现有专家、技能和 MCP 的添加、启停、连接交互全部保留。岗位智能体能力直接进入相同列表，不增加来源标签。

同一资源按资源 ID 去重。数据层保留关联来源，以保证：

- 移除某岗位智能体时，仅删除该岗位贡献的关联；
- 同一能力若还被个人或其他岗位智能体引用，继续保留；
- 岗位停用时只退出当前可用集合，不删除个人配置；
- 实际调用仍受用户权限、资源授权和连接状态限制。

## 5. 现有用户心智与知识

- 用户心智一级区块及岗位说明、能力地图、工作画像、知识地图、目标、工作规则六张卡片全部保留；
- 这些内容继续按当前前台逻辑维护，不因添加岗位智能体而被覆盖；
- 个人知识库可连接本人有权限使用的企业或个人知识资源，但其配置属于个人数字分身；
- 岗位智能体不读取、复制或向后台上传个人知识正文。

## 6. 分身评测与成长记录

现有分身评测保留，用于评估当前个人数字分身的画像完整度和任务表现。它可以综合当前已启用岗位智能体、能力和知识快照。后台岗位智能体的评测与发布机制本期暂缓，不在本 PRD 定义。

添加、启用、停用和移除岗位智能体均形成个人成长事件；事件记录岗位智能体名称、版本、动作和时间。

## 7. 运行记录

个人对话日志展示本人完整记录。每次运行保存实际参与的岗位智能体 ID 与版本列表、使用能力、任务结果和反馈。前台不需要展示能力来源；后台运行记录与受控进化本期暂缓。

V1 允许多个岗位智能体同时启用，不要求用户每次任务手工选择，也不设计复杂的岗位路由、优先级和冲突处理。

## 8. 异常处理

| 场景 | 处理 |
| --- | --- |
| 岗位智能体被后台停用 | 卡片提示“已不可用”，停止参与新任务，引导用户移除 |
| 用户不再命中可添加范围 | 不允许重新启用；历史任务保留；提示移除 |
| 岗位能力失效或无权限 | 能力列表显示不可用状态，不阻塞其他能力使用 |
| 添加时岗位版本已变化 | 使用最新已发布版本，并提示版本已更新 |
| 可添加列表为空 | 显示“当前没有可添加的岗位智能体” |
| 移除岗位后能力仍被其他关系引用 | 能力继续保留，不向用户展示复杂来源解释 |

## 9. 验收场景

1. 用户心智、能力、知识库、分身评测等现有模块均未被删除；
2. 岗位智能体作为一级模块显示在能力上方；
3. 用户可以从可添加弹窗添加多个岗位智能体；
4. 每张岗位智能体卡片支持启停、查看和移除；
5. 添加岗位智能体后，相应技能和 MCP 出现在现有列表中，且不显示来源标签；
6. 同一能力存在多个关联时只显示一条，移除一个关联后仍可正确保留；
7. 个人知识库和用户心智不会被岗位智能体覆盖或上传后台；
8. 个人详情看不到后台草稿及内部操作记录；
9. 多个岗位智能体可同时启用，运行记录可追溯实际参与版本。
