# PRD：双模式会话与统一 Workspace

> 文档版本：V1.3
> 文档状态：产品开发基线
> 更新日期：2026-07-27
> 适用端：COMAC AI 桌面 Web / 桌面客户端内嵌 Web
> 关联文档：《PRD-助理A2A任务派发与催办》《PRD-A2A用户决策与确认机制》《PRD-右侧工作区与输出物预览》《PRD-Workspace工作台交互规范》

## 1. 文档目的与口径

本文定义 COMAC AI 的两种核心工作模式、会话生命周期、逻辑文件目录、统一 Workspace、记忆分层以及跨模式访问规则，是后续助理、普通任务、输出物和 A2A 协作设计的上位信息架构基线。

本文描述正式产品应具备的业务行为，不以当前前端 Demo 的数据结构为正式实现依据。

必须区分：

1. **正式产品口径**：服务端持久化、权限校验、版本控制、审计、检索和真实文件存储；
2. **Demo 口径**：静态 Mock 数据、固定日期、关键词剧本和浏览器内状态，仅用于验证界面与交互；
3. Demo 可以模拟正式流程，但不得把 `localStorage`、前端字符串匹配或硬编码目录写成正式技术方案；
4. 正式产品的“Workspace 文件”是用户可理解的逻辑文件视图，不要求物理存储路径与界面目录一一相同。

## 2. 产品背景

COMAC AI 同时承担两类明显不同的工作：

- 用户为某件具体工作创建一个独立任务，与智能体持续完成该任务；
- 用户长期与自己的个人数字分身交流，让助理记忆偏好、汇总事项、处理文件并代表用户发起受控协作。

如果两类工作共用同一种 Session 和同一个目录，会出现以下问题：

- 普通任务无法保持明确的目标和文件边界；
- 助理被拆成大量短会话，失去连续性；
- 助理记忆、普通任务上下文和 A2A 协作记录相互污染；
- 右侧出现“输出物面板、协作事项面板、记忆面板”等多个并列入口，交互逐渐信息化和复杂化。

因此正式产品采用“两种会话模式 + 一个统一 Workspace”的结构。

## 3. 核心产品原则

1. **普通任务是可创建的独立 Session；助理是唯一的逻辑长 Session。**
2. **自然语言是助理模式的主要操作入口。**
3. **右侧只保留一个统一 Workspace，不再设置独立协作事项侧栏。**
4. **聊天负责表达意图、承载对话内行动卡和反馈结果，Workspace 负责文件查看、定位和预览。**
5. **Session 连续性不等于模型上下文无限增长。**正式产品必须支持压缩、摘要、记忆提炼和按需检索。
6. **文件视图不等于业务事实源。**A2A 任务、组织关系、权限和正式状态仍由权威服务管理。
7. **默认上下文最小化。**不把所有普通任务文件自动注入个人助理上下文。
8. **跨模式访问按需发生。**助理可在用户授权下检索普通任务，但不默认展示或加载全部普通任务内容。

## 4. 术语定义

| 术语 | 定义 |
| --- | --- |
| 普通任务模式 | 用户点击“新建任务”创建的独立工作 Session；一个任务对应一个稳定 Session。 |
| 助理模式 | 用户与自己个人数字分身之间唯一、长期存在的逻辑 Session。 |
| 逻辑长 Session | 产品上连续存在的会话身份；底层允许进行上下文压缩、摘要和记忆检索。 |
| Workspace | 右侧统一工作区，用于查看逻辑目录、打开文件、预览输出物和查看任务文件投影。 |
| 普通任务目录 | 按任务 Session 创建日期归档的文件目录。 |
| Assistant 目录 | 个人助理专属目录，包含助理规则、用户偏好、长期记忆、每日工作记忆、协作任务投影和助理输出物。 |
| 每日工作记忆 | 助理在某自然日形成的工作记录和待提炼上下文，不是新 Session。 |
| 长期记忆 | 经筛选后需要跨时间持续使用的事实、偏好和稳定决策。 |
| 文件投影 | 将结构化服务数据转成用户或 Agent 可读文件的视图；投影不是唯一事实源。 |
| 输出物 | 智能体生成并可被用户预览、下载或继续引用的文件。 |

## 5. 两种模式的边界

| 维度 | 普通任务模式 | 助理模式 |
| --- | --- | --- |
| 创建方式 | 用户可反复创建 | 系统为每个用户创建唯一实例 |
| Session 数量 | 0 到多个 | 逻辑上固定 1 个 |
| 主要目标 | 完成一件明确工作 | 长期个人协助与跨工作协调 |
| 默认上下文 | 当前任务 Session | Assistant 目录、精选长期记忆和按需检索结果 |
| 文件范围 | 当前任务目录 | Assistant 专属目录 |
| 历史组织 | 按创建日期归档，列表按最近活跃排序 | 一个持续会话，不按日期拆成多个会话 |
| 记忆 | 任务内上下文和任务摘要 | 长期记忆 + 每日工作记忆 |
| A2A | 可作为任务来源上下文 | 主要发起、查询、催办和回复入口 |
| 右侧 Workspace | 默认定位当前任务目录 | 默认定位 Assistant 目录 |

## 6. 总体信息架构

```text
Workspace/
├── Assistant/
│   ├── SOUL.md
│   ├── AGENT.md
│   ├── USER.md
│   ├── MEMORY.md
│   ├── memory/
│   │   └── YYYY-MM-DD.md
│   ├── collaboration/
│   │   ├── index.md
│   │   └── tasks/
│   │       └── {collaboration-task-id}.json
│   └── outputs/
│       └── YYYY-MM-DD/
│           └── {artifact-file}
│
└── Tasks/
    └── YYYY-MM-DD/
        └── {task-session-id}-{safe-title}/
            ├── context.md
            ├── attachments/
            └── outputs/
```

### 6.1 本期不设置 Projects 根目录

本期产品只有普通任务模式和助理模式，不将“项目”作为新的一级产品实体。

业务任务可以引用外部型号项目、供应商项目或业务系统记录，但 COMAC AI 不因此创建第二套项目和成员体系。

只有未来明确支持以下能力时，才重新评估 `Projects/`：

- 多个普通任务共享一个长期上下文；
- 用户显式创建、归档和管理项目；
- 项目级成员、权限和共享文件；
- 项目内任务、会话和输出物的统一生命周期。

## 7. 普通任务目录规则

### 7.1 创建

用户创建普通任务 Session 时：

1. 服务端生成全局唯一 `task_session_id`；
2. 记录 `created_at`、`last_active_at`、创建人、标题和状态；
3. 在逻辑目录 `Tasks/YYYY-MM-DD/` 下创建稳定目录；
4. 日期取用户创建时所属时区的自然日；
5. `safe-title` 仅用于可读展示，唯一性由 `task_session_id` 保证。

### 7.2 跨天继续

- Session 创建后目录路径保持不变；
- 用户第二天继续昨天的 Session，不移动目录，不复制目录；
- 继续对话只更新 `last_active_at`；
- 左侧任务历史按 `last_active_at` 倒序展示，而不是按目录日期排序；
- 日期文件夹含义必须明确为“创建日期”。

### 7.3 目录内容

| 路径 | 正式含义 |
| --- | --- |
| `context.md` | 当前任务经压缩后的目标、约束、关键决策和待办摘要。 |
| `attachments/` | 用户上传、外部引用后落盘或受控缓存的附件。 |
| `outputs/` | 当前任务 Session 生成的输出物。 |

完整消息记录、工具调用记录、模型上下文快照和审计日志可由结构化会话服务保存，不要求全部直接暴露在用户文件树中。

### 7.4 标题变化

- 用户修改任务标题时，界面标题立即更新；
- 逻辑目录展示名可以同步更新；
- 底层对象仍以 `task_session_id` 关联，重命名不得导致输出物、消息或引用丢失；
- 正式产品不得通过文件夹名称作为唯一主键。

## 8. Assistant 目录规则

### 8.1 唯一性

- 每个用户默认只有一个 Assistant 目录；
- Assistant 目录与用户主体绑定，不随客户端设备变化；
- 用户重新登录、换设备或客户端离线后恢复时，继续使用同一逻辑长 Session 和同一 Assistant 目录；
- 删除或重置个人助理属于高风险操作，必须提供确认、影响范围说明和可恢复策略。

### 8.2 根文件

| 文件 | 用途 | 默认可见 | 可编辑性 |
| --- | --- | --- | --- |
| `SOUL.md` | 助理人格、沟通原则和价值边界 | 是 | 受控编辑，保留版本 |
| `AGENT.md` | 助理工作规则、能力和工具使用约束 | 是 | 管理员模板 + 用户允许范围 |
| `USER.md` | 助理需要理解的用户偏好和协作习惯 | 是 | 用户可查看、纠正和删除 |
| `MEMORY.md` | 精选长期记忆 | 是 | 用户可查看、纠正、删除；Agent 可建议更新 |

账号姓名、组织、部门、岗位和正式权限不应以 `USER.md` 为权威来源，应实时来自身份和组织系统。

### 8.3 `memory/` 每日工作记忆

每日工作记忆与长 Session 不冲突：

- 长 Session 表示产品上的连续会话；
- 每日工作记忆表示底层为了压缩和检索保存的时间切片；
- 当天没有发生有效助理交互时，不要求创建空文件；
- 同一天多次交互默认写入同一个日期文件；
- 日期按用户时区计算；
- 每日文件可以保存事实候选、临时进展、会话摘要和待提炼内容；
- 每日文件不应自动包含敏感凭证、完整业务数据副本或无关工具日志；
- 定期将稳定、高价值内容提炼到 `MEMORY.md`；
- 已过时内容必须支持降级、删除和保留来源记录。

### 8.4 `collaboration/`

`collaboration/` 用于让用户和 Agent 理解 A2A 协作任务，但不替代任务服务：

| 路径 | 含义 |
| --- | --- |
| `index.md` | 当前协作任务的可读索引和统计摘要。 |
| `tasks/{id}.json` | 某个协作任务的结构化只读投影。 |

投影更新规则：

1. 权威任务发生版本变化后生成新投影；
2. 投影必须包含 `task_id`、`version`、`updated_at` 和权威来源；
3. 投影生成失败不得改变权威任务状态；
4. 用户直接编辑投影文件时，不自动写回正式任务；
5. 如未来支持文件编辑写回，必须经过字段校验、权限检查、并发检查和用户确认；
6. 删除本地投影不得删除权威任务。

### 8.5 `outputs/`

- 助理长 Session 产生的输出物按生成日期归档；
- 日期是输出物生成日期，不是新 Session；
- 输出物对象必须有稳定 `artifact_id`，路径不是唯一标识；
- 同名文件不得静默覆盖，应创建新版本或要求用户确认；
- 输出物可关联一个或多个来源任务、协作任务和普通任务 Session；
- 关联不等于复制，避免同一文件在多个目录形成不一致副本。

## 9. 长 Session 与记忆机制

### 9.1 逻辑连续性

用户始终进入同一个“我的助理”会话。产品不得每天自动创建新的助理会话入口。

### 9.2 上下文装载

每轮请求不应加载 Assistant 目录的全部内容。建议上下文由以下部分组成：

1. 必需的 Agent 规则；
2. 经过预算控制的 `USER.md` 与 `MEMORY.md`；
3. 最近对话窗口或压缩摘要；
4. 与当前问题相关的每日记忆检索结果；
5. 用户显式引用的文件；
6. 经过权限校验的外部或普通任务检索结果。

### 9.3 记忆写入

| 类型 | 示例 | 处理 |
| --- | --- | --- |
| 明确记忆指令 | “记住我喜欢结论先行” | 生成写入建议，按策略确认或自动写入。 |
| 稳定偏好 | 多次表现出的格式偏好 | 提示用户确认后进入长期记忆。 |
| 临时工作进展 | “今天等供应商回复” | 进入每日工作记忆，不直接进入长期记忆。 |
| 敏感信息 | 密钥、口令、个人隐私 | 默认拒绝写入通用记忆，按安全策略处理。 |
| 正式业务状态 | 任务完成、审批通过 | 以权威业务系统为准，记忆仅保存引用或摘要。 |

### 9.4 用户控制

用户必须能够：

- 查看助理保存了什么；
- 纠正错误记忆；
- 删除单条记忆；
- 要求忘记某个主题；
- 查看记忆来源和更新时间；
- 了解删除记忆与删除原始会话、业务记录之间的差异。

## 10. 统一 Workspace 交互

### 10.1 通用规则

- 普通任务和助理模式共用同一个 Workspace 工作台组件；
- 两种模式共用双层导航、顶部标签、输出物浮层、右侧文件导航、内容画布、关闭动作和响应式切换；模式只改变根目录、目录内容与默认选中项；
- 一级顶栏只保留输出物和 Workspace 两个固定按钮；二级上下文栏提供独立文件夹按钮；不提供来源、终端、底部面板和侧边任务；
- 工作视图标签按稳定对象去重；关闭最后标签时 Workspace 和右侧导航自动关闭；
- 点击一级 Workspace 按钮隐藏时保留标签、激活标签和文件目录状态，重新打开后原样恢复；
- 没有标签时打开 Workspace 进入启动器，不自动创建默认文件；
- 点击聊天中的文件卡片或任务文件入口时打开 Workspace；HTML 默认进入受控 Browser，其他文件进入文件标签；
- 用户不能在一期 Browser 中输入网址，只能打开自己生成的 HTML；
- Workspace 打开不改变当前 Session；
- 关闭右侧文件导航不关闭已打开标签；关闭最后标签才退出 Workspace；
- 不再设置“待我处理 / 我发起的”常驻侧栏。
- A2A 用户决策采用对话内结构化行动卡，不属于 Workspace 文件组件、底部 Dock 或居中 Modal；卡片不覆盖输入器，用户可以继续聊天。

### 10.2 模式根目录

| 当前模式 | 默认根目录 |
| --- | --- |
| 新建或历史普通任务 | 当前任务 Session 目录 |
| 助理 | `Assistant/` |

### 10.3 助理模式默认展示

打开 Workspace 后：

1. 右侧导航展示 Assistant 文件树；
2. 默认不展示 `Tasks/` 全量目录；
3. 默认选中上次查看文件；没有记录时可选中 `MEMORY.md` 或展示 Assistant 根目录说明；
4. 点击 Markdown、JSON 或输出物文件，打开或聚焦对应文件标签；
5. 点击协作任务查询结果，打开对应 `collaboration/tasks/{id}.json`；
6. 任务详情属于文件预览内容，不创建第二个协作管理面板。

### 10.4 对话与 Workspace 的关系

| 用户行为 | 对话区 | Workspace |
| --- | --- | --- |
| 问“我有哪些待办” | 返回简洁结构化结果 | 不强制打开 |
| 点击某个待办 | 保持当前对话位置 | 打开任务文件投影 |
| 说“催一下张三” | 在消息流生成催办行动卡；输入器保持可用 | 当前文件保持 |
| Workspace 中收到需本人处理的 A2A 事项 | 事件写入助理对话；不强制切回对话 | 当前 Workspace 现场保持，助理入口或待确认提示点亮 |
| 点击输出物卡片 | 保持消息 | 打开文件预览 |
| 打开 Workspace 按钮 | 不新增消息 | 有标签时恢复原现场；无标签时打开启动器 |

### 10.5 中小窗口

- 宽屏允许对话与 Workspace 并排；
- 中等窗口无法保证两侧最小可用宽度时，Workspace 覆盖当前主工作区，通过一级 Workspace 按钮返回对话；
- 移动端采用对话与 Workspace 单页切换，Workspace 内文件树与预览使用可操作的单列布局，不强行展示桌面双栏；
- 所有尺寸不得出现页面级横向滚动；
- 返回对话后保留滚动位置、输入草稿和已选文件。

## 11. 普通任务与助理的跨模式访问

### 11.1 默认隔离

- Assistant Workspace 默认不显示全部普通任务目录；
- 普通任务上下文不自动进入助理模型上下文；
- 一个普通任务不得读取另一个普通任务的文件，除非用户明确引用且权限允许。

### 11.2 助理按需检索

用户提出“昨天那个报告”“我上周做过什么”等跨任务问题时：

1. 助理识别需要跨任务检索；
2. 使用用户权限检索普通任务索引；
3. 若命中唯一结果，返回摘要和来源；
4. 若命中多个结果，要求用户选择；
5. 用户点击来源后，Workspace 可临时打开对应任务文件；
6. 临时打开不把该普通任务目录永久移动到 Assistant 下；
7. 高敏感目录按策略要求再次确认。

“默认不展示”不等于“能力上永久不可访问”。完全隔离会使个人助理失去跨任务回忆和协调价值。

## 12. 正式数据对象

### 12.1 Session

至少包含：

- `session_id`
- `session_type`: `task` / `assistant`
- `owner_user_id`
- `title`
- `created_at`
- `last_active_at`
- `status`
- `context_summary_version`
- `workspace_root_id`

约束：每个用户只能有一个有效的 `assistant` Session；普通任务 Session 不限制数量。

### 12.2 WorkspaceNode

至少包含：

- `node_id`
- `workspace_id`
- `parent_node_id`
- `node_type`: `folder` / `file` / `virtual_file`
- `display_name`
- `object_ref`
- `mime_type`
- `created_at`
- `updated_at`
- `version`
- `permission_policy_id`

### 12.3 MemoryRecord

至少包含：

- `memory_id`
- `owner_user_id`
- `memory_type`: `daily` / `long_term` / `user_preference`
- `content`
- `source_refs`
- `sensitivity_level`
- `confidence`
- `created_at`
- `updated_at`
- `expires_at`
- `status`

文件是 MemoryRecord 的展示或导出形式，正式产品应保留来源、版本和删除状态。

### 12.4 Artifact

至少包含：

- `artifact_id`
- `owner_user_id`
- `source_session_id`
- `source_message_id`
- `file_name`
- `mime_type`
- `size`
- `storage_ref`
- `preview_status`
- `version`
- `created_at`
- `retention_policy`

## 13. 权限与安全

1. 用户只能看到自己有权限访问的目录和文件；
2. 个人助理不得扩大用户权限；
3. `SOUL.md`、`AGENT.md` 中由组织强制下发的部分不可被用户覆盖；
4. `USER.md` 和 `MEMORY.md` 可能包含个人信息，默认仅用户本人和其个人助理可访问；
5. A2A 只共享完成任务所需的最小上下文，不共享整个 Assistant 目录；
6. 文件预览必须进行 MIME 校验、安全扫描和内容隔离；
7. HTML 预览必须在受控沙箱中运行，禁止默认获取宿主权限；
8. 删除、导出和分享操作必须有审计记录；
9. 任何凭证、密钥和访问令牌不得以明文记忆文件形式长期保存；
10. 用户离职、账号冻结或权限变化后，应立即影响检索与文件访问。

## 14. 服务端能力要求

正式产品至少需要：

- Session 服务：管理两种 Session 和消息历史；
- Workspace 服务：管理逻辑目录、节点、版本和权限；
- Artifact 服务：存储、预览转换、下载和生命周期管理；
- Memory 服务：提炼、检索、来源和用户控制；
- Search 服务：普通任务、文件和记忆的授权检索；
- Collaboration Task 服务：A2A 任务权威状态；
- Audit 服务：记录敏感操作、确认和系统写回；
- Event 服务：同步任务、文件、记忆和客户端状态变化。

客户端不得承担以下权威职责：

- 生成业务任务主键；
- 判断最终权限；
- 保存唯一任务状态；
- 仅依赖浏览器本地数据恢复用户工作；
- 仅依赖文件名关联 Session 或输出物。

## 15. 失败与冲突处理

| 场景 | 产品处理 |
| --- | --- |
| Workspace 加载失败 | 保留对话可用，展示重试，不显示空目录冒充成功。 |
| 文件元数据存在但内容丢失 | 展示文件不可用和错误编号，不静默删除节点。 |
| 文件预览转换中 | 展示转换状态，可稍后刷新。 |
| 记忆写入失败 | 对话说明未保存，不声称已经记住。 |
| 记忆冲突 | 使用版本号检测，展示最新内容并重新合并。 |
| Session 重命名冲突 | 保留稳定 ID，生成可区分展示名。 |
| 跨任务检索无结果 | 说明检索范围，允许用户补充关键词或手动选择任务。 |
| 跨任务检索多结果 | 展示候选来源，不自动选错。 |
| 权限撤销 | 立即停止内容返回，已打开预览进入不可访问态。 |
| 协作投影过期 | 标记“正在刷新”，向权威任务服务重新查询。 |
| 客户端离线 | 允许查看已安全缓存内容；正式写入进入明确待同步状态。 |

## 16. 埋点与效果指标

建议记录：

- 两种模式的进入次数和持续时长；
- Workspace 打开率、关闭率和平均停留时间；
- 从对话卡片打开文件的比例；
- 从文件树主动定位文件的比例；
- 助理任务查询成功率和二次追问率；
- 跨任务检索命中率、候选选择率和误命中反馈；
- 记忆纠正、删除和忘记请求数量；
- Workspace 加载、文件预览和下载失败率；
- 中小窗口下对话/Workspace 切换次数。

不以“打开协作面板次数”作为指标，因为正式产品不再设置该面板。

## 17. 正式验收标准

### 17.1 普通任务模式

- 可连续创建多个普通任务 Session；
- 每个 Session 有稳定唯一 ID 和独立目录；
- 目录按创建日期归档；
- 跨天继续对话不移动目录；
- 左侧历史按最近活跃时间排序；
- Workspace 默认打开当前任务目录；
- 普通任务和助理的 Workspace 外壳与交互一致；
- 普通任务生成物进入当前 Session 的 `outputs/`，点击聊天卡片后在文件树中定位并预览；
- 一个任务的输出物不会自动出现在另一个任务目录。

### 17.2 助理模式

- 每个用户只有一个有效助理长 Session；
- 重新进入时恢复同一会话；
- Workspace 默认根目录为 Assistant；
- 可查看根文件、每日记忆、协作任务投影和助理输出物；
- 每日记忆文件的创建不产生新的助理 Session；
- 不出现独立“待我处理 / 我发起的”右侧面板；
- 查询待办时结果出现在对话中；
- 点击查询结果在统一 Workspace 中打开任务文件。

### 17.3 权限与可靠性

- 助理不默认加载全部普通任务；
- 按需检索必须使用用户权限；
- 删除投影文件不删除权威任务；
- 记忆可查看、纠正和删除；
- 关键写入失败时不得展示成功；
- 所有正式外部动作保留确认和审计记录。

### 17.4 响应式

- 宽屏下对话和 Workspace 可并排使用；
- 中等窗口下 Workspace 可独占主工作区并明确返回；
- 移动端不出现不可操作的压缩双栏；
- 所有支持尺寸无页面级横向滚动；
- 切换后保留输入草稿、对话位置和文件选择。

## 18. 当前 Demo 实现说明

当前前端 Demo 只验证交互方向：

- 使用一个固定助理长会话页面；
- Assistant 文件树、记忆文件、输出物和任务文件全部为前端静态 Mock；
- 每日文件日期固定，不代表真实时区和服务端生成逻辑；
- A2A 任务文件由前端 Mock 对象即时生成；
- 关键词触发待办查询、派发、催办和回复剧本；
- 不创建真实物理目录，不读写用户磁盘；
- 不连接 Workspace、Memory、Artifact、Session、权限、组织或 A2A 服务；
- 不实现普通任务按日期创建物理目录；
- 不代表正式产品使用 JSON 文件作为任务权威存储；
- 不代表正式产品使用 Markdown 文件直接承载全部模型上下文。

Demo 验收只说明界面和操作路径可演示，不能替代正式接口、状态机、安全和性能验收。

## 19. 待确认事项

1. `SOUL.md` 和 `AGENT.md` 中用户可编辑与组织强制内容的边界；
2. 每日工作记忆的保留周期和自动清理策略；
3. 长期记忆写入是否逐条确认，还是按敏感级别分层；
4. 用户是否可在右侧直接编辑 Markdown 文件；
5. Assistant 输出物是否允许手动移动到普通任务目录；
6. 跨任务检索的默认时间范围；
7. 普通任务删除后输出物和记忆引用的保留策略；
8. 移动端 Workspace 一期是否完整支持文件树和预览；
9. 未来引入 Projects 模式的触发条件与迁移方式。
